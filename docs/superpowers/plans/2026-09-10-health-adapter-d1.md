## Global Constraints

- Accepted RC2 core, artifacts, tags, and all existing production semantics remain unchanged.
- Existing spikes/health_coverage, spikes/health_catalogue, and spikes/health_steps files remain byte-identical.
- No store initialization/publication, FetchResult mapping, metric registration, mesh sync change, new MCP tool, or weekly-report integration.
- Every date and full original report field survives: observation_completeness="unknown", valid_metric_day=null, inference_eligible=false.
- No real source names, records, identifiers, paths, selection metadata, or measurements enter public files, logs, tests, or commits. Synthetic data only.
- Every admitted result requires fresh independent replay of the exact input bytes. Prior receipts and hashes alone cannot admit data.
- Derive the actual definition from verified binding, actual pinned report timezone, and supported rule constants; compare full canonical actual and expected contents before success.
- Batch content is deterministic and immutable. Execution identity/timing belongs only in separate receipts. Unsupported versions and malformed structures fail closed with fixed codes.

Create a small separate Python package at adapters/health_observations/ with focused modules for contracts, preparation, and command entry. New tests live in tests/health_observations/. Keep all existing source modules and tests unchanged. Add docs/HEALTH_ADAPTER_D1.md, a concise README link, and one CI command for the new tests. Do not change pyproject.toml, uv.lock, RC2 schemas, or the accepted design document. Update this plan only if the controller rules on a conflict.

Binding constraints: RC2 and existing spike files unchanged; no stores/collector/report/MCP wiring; all daily states/nulls/counts/reasons/boundaries/coverage flags preserved exactly; synthetic public evidence only; fresh replay before admission; derived actual definition equals configured expected content; immutable deterministic batch separated from operational receipt; strict safe failures.

Implement a clear public Python API around prepare_observations(input_set, expected_definition). Return an immutable prepared result containing deterministic batch bytes and separate verification receipt bytes, with convenience accessors returning defensive decoded copies if helpful. The result is not a persisted store handle and cannot attest future D2 publication. Use exact domain-separated definition/batch hashing from the spec. Provide executable JSON Schema/type contracts plus semantic validators for definition, batch, receipt, and safe failure. Semantic validation must enforce exact scalar types, relationships, canonical hashes, supported rule mapping, coverage flags, and private envelopes; JSON Schema cannot replace replay. Document which checks are structural versus independently recomputed. Do not duplicate the evaluator's numeric/time logic in the adapter.

Make the pipeline wrap the unchanged evaluator and unchanged independent verifier through their public interfaces. Their sibling-import conventions must not pollute the host module namespace; subprocesses using the running interpreter are an acceptable isolation mechanism. Preserve unexpected diagnostics privately only if needed; CLI stdout/stderr must not include private payloads/paths or arbitrary exception text. Record actual producer/verifier code content identities and runtime/resource envelope in the receipt, not invented commit provenance or caller-supplied PASS.

Support evaluating from archive/catalogue/binding plus explicit timezone/as_of/days, and accepting an existing report for fresh admission/replay (including rehashed-tamper refusal). A supplied report is never trusted, repaired, or modified. Because the verifier reconstructs from the report's own operating inputs, independently require report window/as_of/days and timezone key to match the requested operating inputs before success; the derived actual definition also binds its actual pinned TZif digest. For newly evaluated reports, no production-policy changes, alternate timezone arithmetic, defaults, or source selection. Verification must bind the returned bytes, not a later reread or mutable caller dictionary. Use private per-operation snapshots/scratch with cleanup on every path to eliminate verify/reopen races. Original inputs stay unchanged; check their identity across the operation. Scratch is not an observation store. Reject aliases/outputs that could overwrite inputs, existing files, or write private payloads into a code checkout; use 0700 directories/0600 files and exclusive complete output publication.

The definition contains the selected finite sorted steps group set, source scope, catalogue descriptor/hash version, pinned timezone key/digest, metric/unit/schema, and a complete documented mapping for the supported steps policy's value interpretation rules. Resource limits are operational receipt metadata, not coverage criteria. Archive/window/paths/times/unrelated catalogue groups are excluded from the definition. Archive/catalogue/binding/report digests determine batch identity as specified. Complete source catalogue/binding/report envelopes remain in the private batch. Never merge batches or invent biological-record identity.

Provide a practical CLI bootstrap: a definition-inspection operation runs full evaluation/replay and writes only the derived definition privately for explicit configuration; the prepare operation requires that expected definition and compares it against a freshly derived one. Document that inspecting a definition does not choose sources, prove user intent, or admit a prepared batch. CLI public output is a fixed status/operation/error code envelope, while actual definition/prepared result goes only to the explicit private output. No caller receipt/verified boolean parameter exists. Definition conflict must include both content identities and fixed differing field names in a private typed failure result; public error stays fixed. Explain retry/new definition remediation without implementing stores.

Write meaningful focused synthetic tests before/during implementation. Use actual public commands for end-to-end tests, no mocking verification into PASS. Focused fault injection can establish clean refusal but cannot substitute for real happy-path replay. Avoid repetitive expensive full-window tests; small invented windows suffice except a specific coverage regression.
