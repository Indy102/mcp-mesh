## Global Constraints

- Accepted RC2 core, artifacts, tags, existing production semantics, all existing spikes, D1 modules/tests/contracts and dependency files remain byte-identical.
- New observation_store package only; no RC2 collector/report/mesh/MCP integration, source selection, numeric projection, coverage promotion, backup/restore, or automatic orphan cleanup.
- Preserve every D1 batch byte and all coverage flags: observation_completeness="unknown", valid_metric_day=null, inference_eligible=false.
- No personal source names, identifiers, records, paths or measurements in tracked files, public output or tests. Synthetic fixtures only.
- Every new import performs fresh D1 preparation; no API accepts a caller-prepared batch or PASS. Expected/actual/stored complete definitions agree before every store write.
- Immutable successful attempt receipt is sole visibility point. All named objects complete, verified, flushed first. No clobber or old-result fallback. Unknown publication stays unknown until explicit recovery.
- Local fsync and process interruption tests do not establish APFS power-loss durability or backup/restore. State these outstanding gates plainly.

## Task 1: Strict storage contracts and safe filesystem primitives

Read docs/superpowers/specs/2026-09-11-health-storage-d2-design.md first; it is binding for all exact strings/fields/order. Also read the D1 public contracts and preparation API and docs/superpowers/specs/2026-09-10-health-observation-adapter-design.md sections 4–6. Implement only the foundation used by Task 2, not a second store orchestration.

Create observation_store/__init__.py (minimal placeholder), contracts.py, filesystem.py, errors.py, and tests/observation_store/test_contracts.py and test_filesystem.py. Existing files unchanged. No dependencies added. All Global Constraints above apply verbatim: preserve RC2/D1/spikes/dependencies; new separate store only; unknown coverage unchanged; synthetic privacy; fresh replay admission; full definition refusal before writes; sole receipt commit point; no power-loss/backup claim. Do not write inside real Health paths or read personal data.

Contracts implement exact manifest/intent/result wire objects from D2 spec, closed schemas and semantic validators. Reuse public D1 canonical/digest/strict_load/validate_definition/definition_id/validate_batch/validate_receipt/identities, not private helpers or duplicated scientific arithmetic. D1 validate_receipt supports optional batch=None: use batchless validation for interrupted intents; use full validation with retained batch before committed visibility. Cross-check store, definition, attempt filename/UUID, D1 verification UUID distinct from D2 attempt, identities and canonical hashes. Semantic validation must reject booleans as integers, floats as integer counts, duplicate JSON keys, nonfinite values, malformed digest/UUID/time, unknown fields/versions and inconsistent outcome nullability.

Fix exact additional closed operation/failure schemas in this module and document their fields in the report for Task 2. Use result envelope contracts for status, metadata-list, recovery, and safe failures. Metadata-list includes store_id, definition_id, sorted deduplicated batch entries with batch_id/definition_id/archive_sha256/report_sha256/committed_attempt_ids. Recovery includes store_id/attempt_id/outcome (COMMITTED/FAILED/INTERRUPTED/NOT_RECORDED), nullable batch_id, nullable fixed error; only COMMITTED may contain batch_id. Safe StoreError exposes fixed code, optional safe store/attempt IDs and optional typed definition conflict (both IDs plus sorted fixed differing field names); no arbitrary exception text. Codes include the spec's list plus INPUT_INVALID, OUTPUT_INVALID, OUTPUT_EXISTS, OUTPUT_NOT_PRIVATE, CLI_USAGE, INTERNAL_ERROR, PLATFORM_UNSUPPORTED. StoreError is shared across modules. Function names validate_manifest, validate_intent, validate_result, validate_listing, validate_recovery, validate_failure; return validated value or safe error. Canonical serialized bytes are preferred API outputs for immutable operation evidence.

Filesystem module provides checked dir-fd primitives, no business preparation or receipt logic. Pin private root and child inode identity; use no-follow/nonblocking opens and type/mode/owner checks. Reject code-checkout and RC2 directories/aliases. Initialize only nonexistent destination under an existing private parent; never adopt/chmod an existing root. Task 2 orchestrates creation/manifest publication using these primitives. Permanent lock file is exclusively created by initialization; normal writer opens never create/truncate/change it. Process-local lock registry keyed root dev/inode plus nonblocking flock, rejects same-thread reentry with NESTED_OPERATION and other-thread/process contention WRITER_BUSY. Never recreate lock when missing. Reads need no writer lock.

Use same-filesystem staged file + macOS renameatx_np(RENAME_EXCL) no-clobber publication, full writes (short writes handled; zero progress failure), fsync files/directories, exact-identity reuse, and explicit linkage/flush uncertainty propagation. Expose a structured publication result or error indicating whether linkage may have occurred; Task 2 must distinguish STORAGE_ERROR before terminal link from PUBLICATION_UNKNOWN afterward. No os.replace for managed evidence. All managed files require nlink=1; exclusive rename leaves no staging hardlink. Support macOS only and return PLATFORM_UNSUPPORTED before initialization/import mutation on other platforms, without a nonexclusive/hardlink fallback. Unsupported filesystem errors remain explicit. The local rename(2) manual is primary interface evidence; RENAME_EXCL is 0x4, measured in the disposable collision probe. Checked handles must not be redirected by swapped descendants, and root replacement detected. No promise against hostile same-user edits after validation.

Provide source archive capture through one regular-file handle with hash/size, before/after identity checks including path identity; reject observed content changes and use D1's documented ctime-only metadata exception. Source copy is performed on every import, including reuse. No requirement to copy catalogue/binding/report a second time: D1 batch embeds them.

Keep the internal API small and document exact signatures in task report for Task 2. Unit tests use synthetic bytes and a small D1-compatible synthetic fixture when needed; they are not fresh replay acceptance. Test permissions, owners, no-follow/FIFO/hardlink/outside aliases, initialization races, lock threads/process/aliases/nested mutation, no-clobber identical vs different bytes, short write/zero write/ENOSPC/flush errors and linkage reporting, checked-dir replacement and source mutation. Use finite bounded subprocess synchronization, no sleeps as correctness assertions. Never enable a production bypass.

No subagents, push or merge. Run .venv/bin/python -m unittest discover -s tests/observation_store -p 'test_*.py' -v; self-review, commit task files only. Full existing suite belongs to Task 2 because this task cannot change old files. Write complete report to controller-provided file: changes, exact internal/public signatures and schemas, commands/counts/exits, self-review, concerns. Return status, commits, one-line tests only. ## Task 2: Store orchestration, private CLI and interruption acceptance

Read docs/superpowers/specs/2026-09-11-health-storage-d2-design.md first and Task 1's report supplied by controller for exact foundation APIs. Follow all its publication/recovery order and error semantics. All Global Constraints apply verbatim: preserve RC2/D1/spikes/dependencies; separate store only; coverage unchanged; synthetic privacy; every new import fresh D1; full definition equality before writes; one success-receipt visibility point; no power-loss/backup claim.

Create observation_store/store.py, __main__.py, export public APIs from __init__.py; add tests/observation_store/test_store.py, test_cli.py, test_interruption.py and focused synthetic fixture/worker helpers as necessary. Task 1 foundation edits only when required for integration, covered by review. Add docs/HEALTH_STORAGE_D2.md and concise README and .github/workflows/verify.yml entry. No existing implementation/test file changes and no dependency change. No reads of private Health data. Do not spawn subagents, push or merge.

Expose initialize(store_dir, store_id, expected_definition), status(store_dir, store_id), import_observations(store_dir, store_id, input_set, expected_definition, attempt_id), read_batch(store_dir, store_id, batch_id), list_batches(store_dir, store_id), recover_attempt(store_dir, store_id, expected_definition, attempt_id). Return canonical immutable bytes (manifest/status, result, exact D1 batch, list/recovery respectively) and fixed StoreError failure bytes/code. Import returns FAILED result bytes only when that terminal failure was recorded; it raises StoreError if no terminal failure record is available or publication is unknown. CLI must treat FAILED bytes as failure, emit fixed FAIL, and retain that private terminal evidence. Definition conflicts always raise without stored result. No public commit(prepared), receipt, success flag, generation reset, destroy, repair or cleanup API.

Hold checked existing writer lock throughout preparation/publication. Compare expected/stored before any store mutation, prepare D1 from original inputs privately outside store, compare actual/expected/stored, revalidate manifest before intent. Definition invalid/conflict is strictly write-free. Other preparation failure may record FAILED under matching expected definition, but no false durable claim if record writing fails. Publish intent then fresh copied/archive-hash-checked raw ZIP plus unchanged batch, all validated in final paths and flushed, then one immutable result. New duplicate attempt ID refuses before writes/replay; new attempt for duplicate batch replays anew and retains new D1 receipt. Guard manifest/root identity before publication, all linked chain relationships and immutable object reuse. Preserve staging/orphans, do not auto-adopt or cleanup.

Implement exact read/list/recover/status as spec. Status can resolve post-manifest initialization flush uncertainty under existing lock; partial root with absent manifest UNINITIALIZED, malformed complete layout INTEGRITY_ERROR. Readers validate successful result+intent+full D1 batch/receipt+retained archive bytes. Listing captures names once and returns metadata only after complete validation; failed/interrupted records must also validate links/null rules. Corruption produces safe explicit failure, never skipped or old fallback. Recovery locks, validates expected definition before writes, reflushes complete committed evidence to resolve unknown, records interrupted valid intent with no result without promoting orphan files, returns observed NOT_RECORDED only for absence. It never retries admission itself.

CLI python -m observation_store supports init/status/import/read/list/recover with explicit --store, --store-id, --attempt-id/--batch-id as appropriate, --definition for init/import/recover, D1 import input options. Explicit new private --output for results and optional --failure-output. Public stdout/stderr uses exactly status/operation/error fields including argparse/unexpected failures, no user arguments, IDs, payloads or exception strings. Task1's operation acknowledgement with safe IDs may be private evidence but is not the public stdout envelope; public success uses error=null. Private files contain canonical full objects, created atomically/exclusively mode0600 under0700 parent outside repos/stores/input aliases. Refuse invalid output locators before store mutation. If output publication fails after committed store result, public PUBLICATION_UNKNOWN with attempt available privately, never unchanged/success claim; recover by original caller attempt ID. Document command exit codes, safe retry/newstore policy, immutable IDs, privacy and evidence limits.

Test hook is observation_store.store._checkpoint(phase: str), a private no-op function, with no environment/CLI toggle. Root checkpoints fixed: initialized-root, before-manifest, after-manifest-publish, prepared, after-intent, after-archive, after-batch, before-result, after-result-publish, after-result-flush. Subprocess test worker can monkeypatch privately to notify/pause, parent kills it. Public happy paths always real D1 evaluation/replay. Test data invented. Test fault injection must establish failure behavior only, never substitute fake PASS for acceptance.
