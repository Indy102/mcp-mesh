# D3: private single-batch Health presentation

Status: implementation specification. Base: `06392108e3cf815aa9098eb6ae83bfdd3dddad6e` (D2). User authorized D3. The accepted RC2, D1, D2 and their contracts remain unchanged. This is the presentation stage of the existing Health observation architecture, not acceptance of the whole project.

## 1. Deliverable and boundary

A separate `observation_view` Python package produces a new, private, self-contained HTML snapshot from one explicitly requested committed D2 batch. No web server, JavaScript, remote assets, MCP tools, refresh, implicit latest batch, batch merging, source selection, comparisons, totals, means, coverage percentages, inference, recommendations or RC2 integration. No D1/D2 implementation, test, schema or dependency edits. New package, tests, docs and additive README/CI entries only.

Static HTML is chosen because it is readable offline without a new server or protocol boundary. Plain JSON already exists in D2; a live dashboard or MCP endpoint adds state and exposure unnecessary for this milestone. A user chooses an ID from the existing D2 list interface, then explicitly supplies it. There is no in-browser store access or picker in D3.

## 2. Public interface and trust boundary

Expose only `create_view(store_dir, store_id, batch_id, output)` and `ViewError` from `observation_view`. The API returns canonical JSON bytes of the same safe acknowledgement emitted by the CLI: exactly `{status, operation, error}`, with `operation="view"`, `status="PASS"`, `error=null` on success. Failures raise `ViewError` with a fixed code and fixed safe acknowledgement bytes. No paths, IDs, user-controlled exception text, Health data, or arbitrary error strings in public output. The CLI `python -m observation_view --store PATH --store-id UUID --batch-id SHA256 --output NEW_PRIVATE_HTML` returns 0 on success, 2 on refusal/failure, empty stderr. Malformed arguments use `CLI_USAGE`; unexpected errors use `INTERNAL_ERROR`. No input batch, receipt, PASS, override, prepared or verification flag is accepted.

Validate explicit IDs with existing public D2/D1 identity contracts or equivalently strict syntax before reading. Validate destination before reading private content. Obtain exactly one batch through public `observation_store.read_batch(store_dir, store_id, batch_id)`, strict-load and validate it through D1, and verify returned batch_id equals the request. Do not read store internals or call init, import, status, recover, listing or preparation. D2 errors remain fixed explicit failures, with no skip, fallback or raw file bypass. Private renderer helpers may be pure for testability, but no public verified-view API accepts caller-supplied data. The store is byte/tree unchanged on success and every D3 failure.

## 3. Exact observation presentation

Render every report day once in its stored order. Use the stored window and timezone; `as_of` is exclusive. Values use exact finite JSON-number round-trip spelling, including explicit zero; do not round to a summary statistic. The metric label is “Selected-source recorded steps”, not total activity or complete daily steps. Show `null` literally for null values, together with the calculation state and reason codes.

Four states: `computed` is the selected-source recorded quantity; `no_records` means no selected occurrences assigned to that date in this archive and is not zero activity; `blocked` preserves all reasons and no substituted value; `no_civil_day` is a skipped local date with null UTC boundaries and zero duration. All eight reason codes remain visible alongside plain-language explanations: `selection_unresolved`, `selected_time_unattributable`, `invalid_selected_record`, `cross_day_quantity_unallocated`, `selected_quantity_overlap`, `selected_repeat_candidate`, `numeric_result_out_of_range`, `no_civil_day`. Do not reinterpret or fix them.

For each day retain exact date, UTC start/end/duration, value, state, reasons, all selected/excluded/unresolved counts, repeat_candidate_extras, both nullable overlap diagnostics, observation_completeness, valid_metric_day, and inference_eligible. Native per-day details can hold diagnostics. Null diagnostics mean unknown, not false. Prominently show `observation_completeness="unknown"`, `valid_metric_day=null`, `inference_eligible=false`; repeat these in exact daily details. Do not derive valid-day counts or completeness from records.

Include family reasons separately. Preserve archive versus window counts and repeat-extra scopes. A report evidence appendix contains the complete exact report object as HTML-escaped canonical JSON in a `pre` element, with a fixed ID `report-json`; parsed text must recover the original report object and all original numeric/null/boolean values. This includes pinned timezone bytes: no timezone recalculation. It is evidence for this snapshot, not a substitute for the D2 batch. Each main row uses a fixed class `observation-day`, has one `time` element with the date as text, and separate fixed classes `value`, `state`, and `reasons`, so independent inspection can compare the primary presentation as well as the appendix. No dynamic attribute values are needed.

## 4. Source, identities and verification language

Display store ID supplied by the caller, batch ID, definition ID, archive hash/length/XML member, catalogue/binding/report digests, report schema/policy/producer versions, selected group IDs/source_scope, window and timezone key/digest. Definition may be shown in escaped canonical JSON. Selected descriptor groups are looked up by exact ID only in `catalogue.families.steps`; descriptor slots are sourceName, sourceVersion, device. Missing and present-but-empty differ. Do not include unrelated HRV/sleep source groups. Source labels describe the export, not authenticated device identity. Binding human assertions may be omitted; if shown label them as assertions. Show that device identity, user intent and Health source priority are not independently verified.

State: “D2 validated the committed batch and linked evidence when this view was generated.” Explain that rendering does not rerun independent source replay, expose execution receipts, verify completeness, authenticate device identity, establish backup or power-loss safety, or continuously check the backing store. No invented replay time, runtime hash, execution identity or attempt ID. If a UTC generation timestamp is included, label it as view generation only. Static output may outlive or disagree with later store state; rerender explicitly to revalidate. Do not label the view, all dates or biological observations as verified/complete based on a successful D2 read.

## 5. HTML safety and presentation

Dynamic text only enters escaped text nodes, never markup, URLs, event handlers, attributes, CSS or scripts. Source and other free text must not spoof surrounding labels using bidi/control characters: visibly escape C0/C1 and Unicode bidi/format controls in human labels; exact JSON remains reversible through standard JSON escaping (including non-ASCII) in the evidence appendix. Escape quotes and angle brackets. No source-generated links. Fixed inline CSS only, no resource URLs/imports, scripts, forms, frames, objects, images, external fonts, refresh or network resources. Add fixed CSP `default-src 'none'; style-src 'unsafe-inline'; base-uri 'none'; form-action 'none'` as defense in depth.

Use readable accessible headings, semantic table headers/caption, native keyboard-operable details, sufficient contrast, responsive overflow for long diagnostic material and practical print styling. No animation or dependency added. Main readings, nulls and restrictions must remain visible at narrow widths; source IDs and long device strings wrap. The local HTML itself is private Health information. Visual checks use invented data first; real-data screenshots remain private.

## 6. Private output publication

Output must be an explicitly new file, including refusal of existing dangling symlinks. Require an existing current-user-owned 0700 parent, new regular 0600 nlink=1 output, outside the canonical executing source root, detected code checkouts, RC2 trees, selected store, any detectable Health store and aliases. Any path with ancestor markers manifest.json plus writer.lock is a Health store; reject even if different from the selected store. Never chmod/adopt a destination or create parents. Validate before sensitive read, and use checked pinned directory handles through publication.

Reuse non-underscore public filesystem primitives from `observation_store.filesystem` only for D3 output, without changes: reject_location, require_platform, CheckedDir, stage_bytes and publish. D3 owns its output/store exclusion guards and error mapping; no private D2 CLI helpers. Staging is a unique D3-owned file in the destination parent. Publication is atomic/exclusive macOS renameatx_np(RENAME_EXCL); no overwrite/hardlink/os.replace fallback. Output validation/publication is macOS-only, matching D2; HTML opens offline in any modern browser.

Fixed error codes include the existing safe StoreError codes and D3 `OUTPUT_PUBLICATION_UNKNOWN`. Existing destination refuses without overwrite. Before-link failure cannot claim successful output; failure after linkage may leave a complete snapshot but must report OUTPUT_PUBLICATION_UNKNOWN, never success. Do not delete a possibly published destination. Private uncommitted stage files may remain and are not auto-adopted. No backup, hostile same-user isolation, all-filesystem or power-loss guarantee follows from successful fsync calls.

## 7. Acceptance

Synthetic tests cover exact visible numbers including zero/fractional round-trip, all four states/eight reasons, all null and false diagnostics, date/window/timezone boundaries and skipped civil date; exact appendix equality and source-group membership; no aggregation/promotion; and hostile labels/control characters without injected DOM or resources. Real D1->D2->D3 integration validates explicit older/newer overlapping batches with no substitution. Wrong IDs, uncommitted/missing/corrupt chains fail without an output. Compare store tree/bytes before and after success and failure. Verify one public read and no mutating call; accept complete chosen batch or explicit refusal under concurrency.

Test private paths, existing destinations, aliases/code/source-only extraction/other stores, modes/types/symlinks/hardlinks, same-destination race, pinned directory replacement, partial publication/flush failures and CLI privacy. Fault tests never stand in for the real integration path. Old tests remain unchanged and pass; independent acceptance is authored outside implementation and run against clean source extraction. Inspect actual rendered DOM/screenshots at desktop/mobile and verify zero network requests. Read a real committed private batch only after review, check every primary day and exact report appendix, and prove the store did not change. Private evidence must never enter Git/public artifacts.

Out of scope: batch picker, interactive filtering, aggregation, other metrics/adapters, public dashboard, receipt inspection API, storage cleanup, backup/restore, T7/T8/T9 or any claim lifting project DRAFT.
